# CP Debugger - 算法竞赛题代码调试 Skill

## 目的

本 skill 帮助诊断算法竞赛题代码错误。用户提供题目（图片或文字）后，分析 `main.cpp`，找出代码错误原因。标准答案以题目截图中的样例输出为准。

## 使用流程

### 1. 获取题目信息

- **题目图片** → 用视觉能力读取；**文字描述** → 直接读取
- 有**参考题解**（网址/截图/文字）时，获取其算法思路并与 `main.cpp` 对比，帮助定位错误
- 提取关键信息：题目名称、输入/输出格式、数据范围、样例输入输出、时空限制

### 2. 读取代码文件并备份原始代码

- 读取 `main.cpp`（待检查代码）和 `.env`（编译配置 `CXX`、`CXXFLAGS`）；文件不存在则提示用户确认路径
- **备份原始错误代码**（调试过程中会反复修改 `main.cpp`，备份便于后续对比和归档）：

```
cp main.cpp main.cpp.orig                    # Linux
Copy-Item main.cpp main.cpp.orig -Force     # Windows PowerShell
```

- `main.cpp.orig` 保存用户最初的错误代码，调试过程中**不要修改**；归档时如需错误代码从它读取，归档后可删除

### 3. 编译与运行

**只能用 `run.sh`（Linux）/ `run.bat`（Windows）编译运行 `main.cpp`，不要直接调用 `g++`**；编译配置在 `.env` 中。

**每次运行都保存输入输出到编号文件**（便于追溯调试过程，归档时参考）：

1. 确定编号 N：`tmp/input_*.txt` 数量 + 1，格式 `01`、`02`、...
2. 测试输入写入 `tmp/input_0N.txt`，运行并保存输出：

```
./run.sh tmp/input_0N.txt tmp/output_0N.txt   # Linux（不带参数则默认 input.txt/output.txt）
run.bat tmp\input_0N.txt tmp\output_0N.txt    # Windows
```

3. 读取输出，与题目样例对比。每次修改代码后重新编译运行，编号递增，这些文件先不要删除

#### 运行后观察

| 现象                  | 下一步                       |
| --------------------- | ---------------------------- |
| 程序崩溃 / 报系统错误 | RE，进入步骤 5 诊断          |
| 程序长时间无输出      | 疑似 TLE，终止后进入步骤 5   |
| 有输出但答案不对      | WA，进入步骤 5 诊断          |
| 输出与题目样例一致    | 进入步骤 4（暴力对拍验证）   |

### 4. 暴力对拍验证

**样例通过后，只要暴力程序好写，就应进行对拍**，确认修复后的代码在随机数据上也正确：

1. **写暴力程序** `tmp/brute.cpp`：用最朴素、显然正确的算法（通常是 O(n²) 或枚举）实现题目要求，与 `main.cpp` 使用相同的输入输出格式
2. **写数据生成器** `tmp/gen.py`：随机生成小规模合法数据（n 取小，如 ≤ 30；操作数适量），覆盖边界情况（最小/最大范围、负数、区间端点重合等），用 seed 参数化以便复现
3. **编译并对拍**：暴力程序可用 `.env` 中的 `CXX`/`CXXFLAGS` 直接编译（`run.sh` 的限制只针对 `main.cpp`），循环多组 seed 比对输出：

```bash
g++ -O2 -o tmp/brute tmp/brute.cpp   # 用 .env 中的 CXX/CXXFLAGS
for i in $(seq 1 50); do
    python3 tmp/gen.py $i > tmp/stress_in.txt
    ./tmp/main < tmp/stress_in.txt > tmp/stress_out1.txt
    ./tmp/brute < tmp/stress_in.txt > tmp/stress_out2.txt
    if ! diff -q tmp/stress_out1.txt tmp/stress_out2.txt > /dev/null; then
        echo "MISMATCH seed=$i"  # 保存该输入，作为反例进入步骤 5 诊断
        break
    fi
done
```

- **对拍不一致**：把 `tmp/stress_in.txt` 作为反例，回到步骤 3 保存编号输入输出，进入步骤 5 诊断
- **对拍全部通过**：再视数据范围做一次大规模性能测试（生成极限规模输入，计时运行），确认不会 TLE/MLE
- 对拍用的 `brute.cpp`、`gen.py` 等文件保留在 `tmp/` 中，归档完成后由 cp-archiver 统一清理

**不适合对拍的情况**（改用替代验证，不要硬写暴力）：

- 答案不唯一（Special Judge、构造题、多解输出）→ `diff` 无法直接比对，改为写 checker 校验输出合法性，或只比对可确定的部分
- 暴力本身不比正解好写（复杂图论/数据结构综合题）→ 改为手工构造边界小数据（空、单点、极值、退化情形）逐一验证
- 交互题、输出 only 题 → 不适用，跳过

替代验证的用例同样保存到 `tmp/input_0N.txt` / `tmp/output_0N.txt`，并在诊断报告中说明验证方式。

### 5. 诊断分析

根据步骤 3/4 的运行结果，针对问题类型（CE/RE/TLE/WA/MLE）进行诊断。诊断时给出**具体行号**和**精准修复建议**，不要直接重写整个代码。

### 6. 输出诊断报告

以清晰的结构输出：

```
## 诊断报告

### 题目信息
- 题目：xxx
- 数据范围：xxx

### 代码分析
- 算法思路：xxx
- 时间复杂度：xxx
- 编译：✅/❌（有警告则列出）

### 问题定位
[具体指出问题所在，附上行号]

### 修复建议
[给出具体的修改方案和理由]

### 修正代码
[如需要，给出修正后的关键代码片段]
```

## 注意事项

- 不要直接重写整个代码或改变其风格；诊断时给出**具体行号**和精准修复建议
- **每次修改代码后，都要重新执行 编译运行（步骤3）→ 样例比对 → 对拍验证（步骤4）**；样例通过不代表正确，以对拍（或步骤4中的替代验证）通过为修复完成的判据
- 不要用 bits/stdc++.h 头文件
