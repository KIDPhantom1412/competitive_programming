# CP Archiver

根据当前对话，将算法题归档到 `archives/<题目名称>/`，支持首次归档和追加新解法。

## 触发条件

| 模式 | 触发词 |
|------|--------|
| 首次归档 | "归档"、"存档"、"保存这道题" |
| 追加解法 | "追加解法"、"新解法"、"第二种解法" |
| 无对话直接归档 | 用户直接说"归档"，但聊天记录中无题目讨论（即用户已独立完成，未与 AI 交流） |

**无对话直接归档时的处理方式：**
- 主动向用户询问必要信息：`题目名称`、`来源`、`标签`、`一句话题目`、`一句话题解`
- `problem.md`：让用户提供题目描述，或说明"请自行补充"
- `solution_01.md`：根据 `main.cpp` 代码反推思路，或让用户提供
- `samples.md`：从 `input.txt`/`output.txt` 提取，或让用户提供
- `wrong_code.cpp`：无调试过程，注明"未记录"
- `pitfalls.md`：无坑点记录，注明"未记录"

## 归档文件结构

```
archives/<题目名称>/
├── README.md          # 入口：题目概览 + 解法目录
├── problem.md        # 题目描述
├── solution_01.md   # 解法1 题解
├── solution_02.md   # 解法2 题解（追加时新增）
├── correct_code_01.cpp  # 解法1 代码
├── correct_code_02.cpp  # 解法2 代码（追加时新增）
├── wrong_code.cpp    # 最后一次错误代码（覆盖更新）
├── pitfalls.md       # 坑点总结（追加时追加内容）
└── samples.md        # 样例（含说明和坑点标注）
```

## 执行流程

### 1. 判断模式

检查 `archives/<题目名称>/` 是否存在：
- **不存在** → 首次归档，执行步骤 2~4
- **已存在** → 追加模式，跳转步骤 5

### 2. 提取信息（首次归档）

**有对话时**：从对话中提取：

| 字段 | 来源 |
|------|------|
| 题目名称 | 图片/文字描述，若无则根据内容概括 |
| 题目描述 | 图片 OCR 或用户文字 |
| 题解思路 | 对话中的分析过程 |
| 错误代码 | 对话中 main.cpp 的早期版本 |
| 正确代码 | 对话中最终的 main.cpp |
| 坑点 | 调试过程中发现的问题 |
| 样例 | input.txt/output.txt 或对话中的样例 |

题目名称作为目录名时，替换非法字符：`空格→_` `/\:*?"<>|` 删除。

**无对话时**（聊天记录中无题目讨论）：
主动向用户询问以下信息，缺少的注明"未记录"：
- `题目名称`、`来源`、`标签`、`一句话题目`、`一句话题解`
- `problem.md`：让用户提供题目描述，或说明"请自行补充"
- `solution_01.md`：根据 `main.cpp` 代码反推思路，或让用户提供
- `samples.md`：从 `input.txt`/`output.txt` 提取，或让用户提供
- `wrong_code.cpp` / `pitfalls.md`：无调试过程，注明"未记录"

### 3. 写入文件（首次归档）

#### `README.md`

```markdown
# <题目名称>

- **来源**：
- **难度**：
- **标签**：
- **日期**：YYYY-MM-DD

## 一句话题目

（1 句话说明题目在问什么，便于日后复习时快速回忆）

## 一句话题解

（1-2 句话概括核心思路）

## 解法列表

| # | 算法 | 复杂度 | 文件 |
|---|-------|--------|------|
| 1 |  |  | solution_01.md |

## 文件说明

| 文件 | 说明 |
|------|------|
| problem.md | 题目描述 |
| solution_01.md | 解法1 题解 |
| correct_code_01.cpp | 解法1 代码（AC） |
| wrong_code.cpp | 错误代码（含 bug） |
| pitfalls.md | 坑点总结 |
| samples.md | 样例（含说明） |
```

#### `samples.md`（关键文件，含说明和坑点）

格式如下（每个样例用 `---` 分隔）：

```markdown
## 样例

### Sample 1（基本功能）

**输入：**
```
3 5
1 2 3 4 5
2 4 6 8 10
```

**输出：**
```
8
```

**说明：** 基本功能测试，验证基础逻辑。

---

### Sample 2（边界：n=1）

**输入：**
```
1 1
100
```

**输出：**
```
101
```

**说明：** n=1 的边界情况。

---

### Sample 3（⚠️ 坑点：n=0 未处理）

> **坑点：** n=0 时循环不执行，答案应保持初始值，很多人忘记初始化。

**输入：**
```
0 10
```

**输出：**
```
10
```

**说明：** n=0 是常见 WA 点，注意空数组的处理。
```

**格式规则：**
- 样例标题可标注类型：`（基本功能）`、`（边界）`、`（极端数据）`
- 有坑点的样例，标题中加 `⚠️ 坑点：xxx`，内容中用 `> **坑点：** ...` 引用块说明
- 多个样例之间用 `---` 分隔

#### 其他文件

| 文件 | 要点 |
|------|------|
| `problem.md` | 题目、输入格式、输出格式、数据范围、样例 |
| `solution_01.md` | 思路、时间复杂度、空间复杂度、代码关键行说明 |
| `correct_code_01.cpp` | 完整代码，关键行加注释 |
| `wrong_code.cpp` | 有 bug 的版本，错误处加注释说明 |
| `pitfalls.md` | 按时间顺序记录遇到的错误及修复方式 |

### 4. Git 提交并 Push（首次归档）

**Commit Message 格式（Conventional Commits）：**

```
feat(archive): <题目名称> - <一句话题解>

- 来源：<来源>
- 标签：<标签>
- 状态：AC
```

未 AC 时状态写 `WIP`。

**执行命令：**

```powershell
# 第一步：展示归档内容，征求用户意见
# 先输出归档摘要（见下方「归档摘要格式」），询问用户是否满意
# 等待用户确认或提出修改意见
# 用户确认后，再执行以下命令：

git status
git add "archives/<题目名称>/"
git commit -m "feat(archive): <题目名称> - <一句话题解>

- 来源：<来源>
- 标签：<标签>
- 状态：AC"
git push origin master
git log --oneline -3
```

只 `add` `archives/` 目录，不误提交其他文件。

**归档摘要格式（征求用户意见时使用）：**

```
✅ 归档内容预览，请确认是否正确：

📁 路径：archives/<题目名称>/

📝 一句话题目：
  <一句话题目>

💡 一句话题解：
  <一句话题解>

📄 包含文件：
  - README.md       题目概览（题目简述 + 题解概要）
  - problem.md      题目描述
  - solution_01.md 解法1 题解
  - correct_code_01.cpp  解法1 代码
  - wrong_code.cpp  错误代码
  - pitfalls.md     坑点总结
  - samples.md      样例（含说明和坑点）

以上内容是否正确？如需修改请告诉我，确认无误后我将提交并推送。
```

### 5. 追加新解法

**不创建新目录，不覆盖原有文件**，只追加。

**5.1 确定编号：**
```powershell
# 查看已有 solution 文件数，确定下一个编号
(Get-ChildItem "archives/<题目名称>/solution_*.md").Count + 1
# 得到 N，新文件为 solution_0N.md / correct_code_0N.cpp
```

**5.2 新增文件：**
- `solution_0N.md` - 新解法题解
- `correct_code_0N.cpp` - 新解法代码

**5.3 更新已有文件：**
- `README.md`：在「解法列表」表格追加一行
- `pitfalls.md`：如有新坑点，在末尾追加

**5.4 提交 Push：**
```powershell
git add "archives/<题目名称>/"
# 先展示追加内容，征求用户确认
# 输出追加摘要，等待用户确认后再执行：

git add "archives/<题目名称>/"
git commit -m "feat(archive): <题目名称> - 追加解法N：<算法名称>

- 来源：<来源>
- 标签：<标签>
- 状态：AC
- 解法：N/<总解法数>"
git push origin master
git log --oneline -3
```

**追加内容预览格式（征求用户意见时使用）：**

```
✅ 追加解法预览，请确认是否正确：

📁 路径：archives/<题目名称>/
➕ 新增文件：
  - solution_0N.md       解法N 题解
  - correct_code_0N.cpp  解法N 代码

📝 更新文件：
  - README.md（解法列表新增一行）
  - pitfalls.md（如有新坑点）

以上内容是否正确？确认后我将提交并推送。
```

## 注意事项

- 聊天记录缺少某些信息时，对应文件注明"未记录"
- 每次归档（首次或追加）完成后，都必须 `git push origin master`。
- Push 失败时：先 `git pull --rebase origin master`，再重新 push。
- 归档摘要输出格式：
  ```
  ✅ 归档完成！
  📁 路径：archives/<题目名称>/
  📦 Git：<commit hash 前7位> 已 push
  ```
