# 线段树

## 懒标记线段树（区间加法）

> 适用特征：区间加（减）+ 区间和 / 最值查询，线段树最基础的形态。
>
> 每个节点维护区间和 `v` 与懒标记 `d`（尚未下传的区间增量）：
>
> - 整区间被修改覆盖 → 直接更新 `v += (R - L + 1) * d` 并累加懒标记 `d`，不再向下递归。
> - 部分覆盖 → 先 `push` 把懒标记传给两个儿子（儿子的 `v` 按**子区间长度**更新、儿子的 `d` 累加，然后清空自己的 `d`），只递归与目标区间**有交集**的子树，回溯时 `pull` 重算父节点。
> - 查询同理：整区间覆盖直接返回 `v`，否则下传后向有交集的子树递归求和。
>
> 易错点：
>
> - 递归前必须判断交集（`l <= mid` / `r > mid`），否则完全在目标区间外的子树无法命中返回条件，递归不终止爆栈。
> - 更新 `v` 时必须乘区间长度；`push` 也因此需要传入 `L, R` 来算子区间长度。
> - `update` 递归回溯后必须 `pull`，否则父节点的 `v` 过时。
>
> 复杂度：每次修改/查询均为 $O(\log n)$，总复杂度 $O((n + m) \log n)$。

## 多标记线段树（加 / 乘 / 赋值）

> 适用特征：区间同时支持**加、乘、赋值**三种修改（或需要维护幂和等派生信息）时，单一懒标记不够，需要多层懒标记。常见做法是保留 `set / mul / add` 三个标记，语义为：先赋值 `set`（若存在），再乘 `mul`，最后加 `add`。
>
> 若节点还要支持查询 `a_i^p`（p = 1, 2, 3），则需要同时维护 `sum(a_i)`、`sum(a_i^2)`、`sum(a_i^3)`，并用二项式/立方展开式在节点上直接更新。
>
> 易错点：
>
> - **下传顺序固定为 set → mul → add**：`set` 会清空之前的 `mul/add`；`mul` 会同时缩放已有的 `add`；`add` 直接叠加。
> - **查询前必须 `push`**：区间部分覆盖时，进入子树前一定要把当前节点的懒标记下放，否则子节点仍是旧值。
> - **set 标记的哨兵值**：若用 `0` 表示"无 set"，则题目必须保证赋值 `c ≠ 0`；否则需要额外布尔标记区分。
>
> 复杂度：单次操作 `O(log n)`。

## 区间赋值（覆盖）

> 适用特征：区间染色 / 覆盖类问题（海报可见性、插花占位等）。
>
> 区间赋值是**覆盖**操作而非累加：`push` 直接把父节点的赋值标记传给子节点，无需乘区间长度；懒标记不能与「无标记」状态混淆（若赋值值可为 `0`，需要额外的布尔标记区分）。

### 离散化端点

> 当坐标范围很大（如 `10^7`）而实际端点数量很少（如 `≤ 2×10^4`）时，可以把所有端点离散化。但普通离散化会把相邻端点之间的空隙抹掉，导致 `[1,2]` 和 `[4,5]` 被压缩成相邻位置，从而误判为连续。
>
> **核心技巧**：在排序去重后的相邻坐标 `a[i-1]` 和 `a[i]` 之间，若 `a[i] != a[i-1] + 1`，则插入一个代表点（如 `a[i-1] + 1`），使得任何区间在压缩后仍然保持正确的相对位置。
>
> 之后用线段树维护每个压缩位置最终被哪个区间覆盖，按顺序做**区间赋值**，最后统计整棵树上出现的不同颜色数。
>
> 易错点：
>
> - 查询时若当前节点没有统一颜色，必须判断叶子节点并直接返回，否则会无限递归到非法子节点导致 RE。
> - 区间赋值是覆盖操作，不是累加，所以 `push` 是直接赋值给子节点。
>
> 复杂度：`O(n log n)`。

### 二分查找第 k 个空位

> 把每个位置是否被占用看成 0/1 数组，用线段树维护区间和（已占用数），支持区间赋 0 / 赋 1。需要放花时，先查询剩余空位数，再二分找到第 1 个和第 F 个空瓶位置，最后把这段区间赋 1。
>
> 查找第 `k` 个空瓶时，利用单调性：区间 `[start, mid]` 的空瓶数 = 区间长度 - 区间和。用 `lower_bound` 找"空瓶数 ≥ k 的最左位置"，避免把后面的满瓶也包含进来。
>
> 易错点：
>
> - **懒标记必须区分“清空 / 无标记”**：若用 `0` 同时表示“无懒标记”和“清空（赋 0）”，`push` 会忽略清空操作。应增加独立的 `tag` 布尔标志或单独标记存在性。
> - **二分方向不要写反**：找第 `k` 个空位要用 `lower_bound`（最左满足），用 `upper_bound` 风格可能把后面的满瓶错误纳入区间。
>
> 复杂度：每次操作 `O(log n)`。

## 区间合并（维护前缀 / 后缀连续段）

> 适用特征：序列上支持单点“删除 / 恢复”，并需要查询某个位置所在的最长连续存活段长度。
>
> 每个节点维护两个值：
>
> * `pre`：区间左端点开始的最长连续 1 长度。
> * `suf`：区间右端点结束的最长连续 1 长度。
>
> 合并左右子树 `[L, mid]` 与 `[mid+1, R]` 时：
>
> * 若左子树全为 1，则 `pre = (mid - L + 1) + 右.pre`；否则 `pre = 左.pre`。
> * 若右子树全为 1，则 `suf = (R - mid) + 左.suf`；否则 `suf = 右.suf`。
>
> 查询位置 `p` 所在连续段长度时，从根向下走：
>
> * `p` 在左子树：若 `mid - 左.suf < p`，说明 `p` 位于跨越左右子树的段中，答案为 `左.suf + 右.pre`；否则递归左子树。
> * `p` 在右子树：若 `mid + 右.pre >= p`，说明 `p` 位于跨越左右子树的段中，答案为 `左.suf + 右.pre`；否则递归右子树。
>
> 易错点：
>
> * 跨越条件不要写反：左子树看 `suf` 能否“够到”`p`，右子树看 `pre` 能否“够到”`p`。
> * 与“子树全满”比较时，注意左子树长度为 `mid - L + 1`（不是 `mid - L`），右子树长度为 `R - mid`。
> * 若题目支持“恢复最近删除”，用栈记录每次删除的位置即可。
>
> 复杂度：每次修改 / 查询均为 $O(\log n)$。

## 势能线段树（区间开方 / 取模）

> 适用特征：区间开方、区间取模、区间整除等**不满足区间可加性**且每个元素「有效修改」次数有上界的操作。
>
> 这类操作无法使用传统 lazy tag，但每个元素最多被"有效修改"有限次（比如一个数开到约 6 次平方根就变成 1），之后便进入稳态。
>
> **核心技巧**：每个节点额外维护一个 `tag`，标记该区间是否已"稳定"（即所有元素都到了不再变化的状态）。更新时若遇到稳定区间则直接 return（剪枝），否则暴力递归到叶子。
>
> 这样每个叶子在整个生命期内最多被更新 K 次（K 是常数），总均摊复杂度仍是 $O((n + m) \log n)$。
>
> **势能**这个名称来自类比：节点有一个"还需多少次修改才稳定"的势能，势能归零后该节点就再也不被访问。
>
> 易错点：
>
> - `tag` 的判断条件需根据题目保证设计（如"区间全 1""区间最大值 < 模数"等），需确认边界值（如 0）是否破坏判断逻辑。
> - 不能用 lazy tag 替代——开方/取模不满足区间可加性，只能靠剪枝 + 暴力到叶子。
> - 区间和可能溢出 32 位，注意用 `long long`。
>
> 复杂度：每次操作均摊 $O(\log n)$，总复杂度 $O((n + m) \log n)$。

## Segment Tree Beats

> 适用特征：区间 `chmin/chmax` 与区间和、区间最值查询混合出现。
>
> 用于处理**区间取 min / max**（`chmin/chmax`）并与区间和、区间最值查询结合的问题。普通线段树无法对 `chmin/chmax` 使用懒标记，因为该操作不满足区间可加性；但若多维护一个“次大值”和“最大值个数”，就能在很多情况下直接“拍扁”当前区间的最大值，避免递归到叶子。
>
> **每个节点维护**：`mx1`（区间最大值）、`mx2`（区间次大值，严格小于 `mx1`）、`cnt`（`mx1` 出现次数）、`sum`（区间和）。
>
> **区间 chmin(t) 的三种情况**：
>
> 1. `t >= mx1`：整个区间无需修改。
> 2. `mx2 < t < mx1`：只有最大值需要降到 `t`，直接更新 `sum -= (mx1 - t) * cnt`，`mx1 = t`，不再下传。
> 3. `t <= mx2`：可能影响到次大值及以下，必须 `push` 后递归到子节点。
>
> **核心剪枝**：情况 2 让我们可以一次性处理整个区间的“顶部元素”，而不必访问每个叶子。

### 区间最值

> 只涉及 `chmin/chmax` + 区间和/最值查询（如上总述）。chmin 的“拍扁”只作用于最大值集合，`sum` 与 `mx1` 就地更新，`mxb` 概念尚未引入。
>
> 易错点：
>
> - `pull` 合并时必须正确区分左右子节点最大值相等 / 不等的所有分支，并正确计算 `mx2` 与 `cnt`。
> - `push` 不可或缺：父节点的 `mx1` 会作为子节点的上界，查询前也必须下传。
> - 区间和与数值都要用 `long long`，避免 `(mx1 - t) * cnt` 溢出。
> - 叶子节点 `mx2` 可设为 `-1` 或 `-INF`，表示不存在次大值。
>
> 复杂度：均摊 $O((n + m) \log n)$。

#### HDU 5306 Gorgeous Sequence

题目：

题解：

### 历史区间最值

> 在 chmin 的基础上加入**区间加**与**历史最大值**（每次操作后 B = max(B, A)）。区间加不像 chmin 只作用于最大值，因此把加法标记拆成两份：
>
> - `mxda`：作用于**最大值集合**的加法标记；`da`：作用于**非最大值集合**的加法标记
> - `mxdb` / `db`：`mxda` / `da` 在其生命周期内的**历史最大值**（用于回答历史最值）
> - 节点信息在上节基础上增加 `mxb`（区间历史最大值）
>
> **区间加 d**：`mx1/mx2 += d`，`mxb = max(mxb, mx1)`（先加再取）；`mxda += d, da += d`；历史标记更新为 `max(自身, 累加后的新标记)`。
>
> **chmin(t) 命中情况 2**（`mx2 < t < mx1`）时：`sum -= (mx1 - t) * cnt`，`mxda -= (mx1 - t)`，`mx1 = t`——把削掉的部分作为**负增量**并入最大值加法标记，`mxb` 不变（A 变小不影响历史最大）。
>
> **pushTag 合并**（子节点可能已有存量标记）：先算历史最大、再累加：`db = max(db, 旧da + 父db)`，`da += 父da`；`mxdb` 同理。
>
> 易错点：
>
> - **push 归属判断**：父节点被 chmin 后 `mx1[u]` 已降低，而子节点 `mx1` 仍是旧值，用 `mx1[child] == mx1[u]` 判断会错发标记。正确条件：`mx1[child] == mx1[u] - mxda[u]`（父节点剔除自身标记后的底层最大值；子节点 mx1 已含自身标记，不能再减 `mxda[child]`）。
> - **push 后必须清空父节点的全部标记**，否则标记被重复叠加。
> - 历史标记必须取累加后的新值（`max(db, da + d)`），不能写成 `max(db, d)`（加法有负数时两者不等价）。
> - 区间加覆盖判断笔误（`R <= r` 写成 `R <= l` 的对称错误）会导致无限递归段错误。
>
> 复杂度：均摊 $O((n + m) \log n)$。
