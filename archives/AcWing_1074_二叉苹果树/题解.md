# AcWing_1074_二叉苹果树

- **来源**：AcWing 1074
- **标签**：树形 DP、背包 DP、二叉树
- **日期**：2026-07-18

## 一句话题目

给定一棵以 1 为根的二叉树，每条树枝上有一定数目的苹果，要求恰好保留 `Q` 条与根 1 连通的树枝，使得能留住的苹果最多。

## 一句话题解

树形背包：把边权挂在子节点上，用“选节点”的视角做背包；也可以直接以“保留边数”做背包。两种状态定义等价，只是下标差 1。

## 题目描述

有一棵二叉苹果树，如果树枝有分叉，一定是分两叉，即没有只有一个儿子的节点。

这棵树共 `N` 个节点，编号为 1 至 `N`，树根编号一定为 1。

我们用一根树枝两端连接的节点编号描述一根树枝的位置。

一棵苹果树的树枝太多了，需要剪枝。但是一些树枝上长有苹果，给定需要保留的树枝数量，求最多能留住多少苹果。

这里的保留是指最终与 1 号点连通。

### 输入格式

第一行包含两个整数 `N` 和 `Q`，分别表示树的节点数以及要保留的树枝数量。

接下来 `N-1` 行描述树枝信息，每行三个整数，前两个是它连接的节点的编号，第三个数是这根树枝上苹果数量。

### 输出格式

输出仅一行，表示最多能留住的苹果的数量。

### 数据范围

`1 ≤ Q < N ≤ 100`

`N ≠ 1`

每根树枝上苹果不超过 30000 个。

## 解法 1：点权树形背包（推荐）

### 思路

在 rooted tree 里，除根以外的每个节点都有且只有一条父边。因此可以把**每条边权映射到它下方的子节点**上：

- 点 `v` 的权值 = 边 `(v, parent(v))` 的苹果数
- 保留一条边 ↔ 在 DP 里选它对应的子节点

于是“保留 `Q` 条边”等价于“在整棵树里选 `Q+1` 个节点（必须包含根 1）”。

设：

> `f[u][j]`：在以 `u` 为根的子树中，**必须选 `u` 自己**，并且总共选 `j` 个节点时，能获得的最大苹果数。

初始化：

```cpp
size[u] = 1;
f[u][1] = 0;                       // 只选 u 自己，收益为 0
std::fill(f[u] + 2, f[u] + N, -INF); // 选 2 个及以上先设为不可能
```

合并子树 `v`（边权 `w`）时，设从子树 `v` 里选 `k` 个节点，则其余部分选 `j - k` 个节点，同时必须加上边 `(u, v)` 的权值：

```cpp
for (int j = std::min(size[u], m + 1); j >= 1; j--)
    for (int k = 1; k <= std::min(size[v], j - 1); k++)
        f[u][j] = std::max(f[u][j], f[u][j - k] + f[v][k] + w);
```

`j` 倒着循环是为了避免同一个子树被重复选取；`k <= j - 1` 是因为 `u` 自己已经占了一个节点。

最终答案：

```cpp
f[1][m + 1]
```

### 复杂度

- 时间：O(N · Q²)
- 空间：O(N · Q)

### 代码

见 `correct_code_01.cpp`。

### 坑点

1. **边表数组要开两倍**：`E[N * 2]`。原代码用 `E[N]`，当 `N = 59` 时双向边共 116 条，会越界导致段错误。
2. **节点 `u` 必选**：`f[u][0]` 在这种定义下是非法的，代码中虽然没用到，但理论上应置为 `-INF`。
3. **答案是 `f[1][m + 1]` 而不是 `f[1][m]`**：因为根节点本身也占一个“被选”的位置。

## 解法 2：边数树形背包

### 思路

也可以直接以“保留的边数”作为状态：

> `f[u][j]`：在以 `u` 为根的子树中，保留 `j` 条树枝（**不含** `u` 到父节点的边）时，能获得的最大苹果数。

初始化：

```cpp
size[u] = 1;
f[u][0] = 0;
std::fill(f[u] + 1, f[u] + N, -INF);
```

合并子树 `v`（边权 `w`）时，从 `v` 子树保留 `k` 条边，再加上 `u-v` 这条边，共占用 `k + 1` 条边：

```cpp
for (int j = std::min(size[u], m); j >= 0; j--)
    for (int k = 0; k <= std::min(size[v], j - 1); k++)
        f[u][j] = std::max(f[u][j], f[u][j - k - 1] + f[v][k] + w);
```

`k` 从 0 开始表示“只保留 `u-v` 这条边，子树 `v` 里不再保留其它边”。

最终答案：

```cpp
f[1][m]
```

### 复杂度

- 时间：O(N · Q²)
- 空间：O(N · Q)

### 代码

见 `correct_code_02.cpp`。

### 坑点

1. 同样要注意 **边表数组开两倍**。
2. 内层循环的上界是 `j - 1`，不要忘记 `-1`（因为还要多花一条边连到子树 `v`）。
3. 初始错误代码里把“父边”硬塞进 `f[u][1]`，导致状态语义混乱；改用“保留边数”版本后，所有边都在转移时显式加入，更不容易出错。

## 初始错误代码参考

```cpp
void dfs(int u, int p) {
    size[u] = 1;
    std::fill(f[u] + 2, f[u] + N, -INF);
    if (p != -1) {
        f[u][1] = E[p].w;   // 把父边塞进 f[u][1]，状态语义混乱
    }
    for (int i = H[u]; i; i = E[i].n) {
        if (i != (p ^ 1)) {
            int v = E[i].v;
            dfs(v, i);
            size[u] += size[v];
            for (int j = std::min(size[u], m); j >= 0; j--) {
                for (int k = std::max(0, j - (size[u] - size[v])); k <= std::min(size[v], j); k++) {
                    f[u][j] = std::max(f[u][j], f[v][k] + f[u][j - k]);
                }
            }
        }
    }
}
```

主要问题：

1. 内层循环没有 `k <= j` 限制，导致 `j - k` 为负数，越界读取到上一行数组的 `0`。
2. 把父边权值作为 `f[u][1]` 的初始值，导致“保留父边”和“不保留父边”的状态混在一起，最终会把不与根连通的分支错误计入答案。
