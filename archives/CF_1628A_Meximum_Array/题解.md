# CF 1628A Meximum Array

- **来源**：Codeforces 1628A（Codeforces Round 767, Div. 1），难度 1400
- **标签**：贪心、构造、二分（题目标签：binary search, constructive algorithms, greedy, implementation, math, two pointers）
- **日期**：2026-11-18

## 一句话题目

给定非负整数数组 $a$，反复从 $a$ 的开头取出一段前缀、把这段前缀的 MEX 追加到 $b$ 末尾，问能构造出的字典序最大的 $b$。

## 一句话题解

每一段都让 MEX 尽量大：设剩余后缀 $a[i..n]$ 的 MEX 为 $M$，则下一个答案元素最大只能是 $M$；再在该约束下把段切得尽可能短（右端点取 $0 \sim M-1$ 在 $i$ 之后首次出现位置的最大值），把 $M$ 加入答案后从下一位置继续贪心。

## 题目描述

给定一个长度为 $n$ 的非负整数数组 $a$，按如下方式构造新数组 $b$：

当 $a$ 非空时：

- 选择一个整数 $k$（$1 \le k \le |a|$）；
- 把当前 $a$ 的前 $k$ 个数的 MEX 追加到 $b$ 末尾，并把这前 $k$ 个数从 $a$ 中删除（剩余元素前移）。

要求让最终的 $b$ **字典序最大**。字典序比较规则：在第一个不同的位置，$x_i > y_i$ 则 $x$ 更大；或者 $y$ 是 $x$ 的前缀且 $|x| > |y|$ 时 $x$ 更大。

一个集合的 MEX 是最小的不属于该集合的非负整数，例如 $\mathrm{MEX}(\{1,2,3\}) = 0$、$\mathrm{MEX}(\{0,1,2,4,5\}) = 3$。

### 输入格式

第一行一个整数 $t$（$1 \le t \le 100$），表示测试数据组数。

每组数据第一行一个整数 $n$（$1 \le n \le 2 \cdot 10^5$），第二行 $n$ 个整数 $a_1, \dots, a_n$（$0 \le a_i \le n$）。

保证所有测试数据的 $n$ 之和不超过 $2 \cdot 10^5$。

### 输出格式

每组数据输出 $m$（最大数组 $b$ 的长度），随后输出 $m$ 个整数表示 $b$ 的元素。

## 解法 1：贪心 + 每个值的最早出现位置（lower_bound）

### 思路

**关键观察 1（上界）**：对固定的起点 $i$，段越长，段内元素集合只会变大，所以 MEX 单调不减：

$$
\mathrm{MEX}(a[i..j]) \le \mathrm{MEX}(a[i..n]) = M
$$

因此无论这一段取多长，$b$ 的下一个元素都不可能超过后缀 MEX $M$。

**关键观察 2（取到 $M$ 的充要条件）**：$M$ 在整条后缀 $a[i..n]$ 中根本不出现。于是只要段内**包含 $0, 1, \dots, M-1$ 全部**，段 MEX 就恰好是 $M$（$M$ 缺席保证了不会更大）。由此可知最短的合法右端点，就是这些值在 $i$ 之后**首次出现位置的最大值**：

$$
j = \max_{0 \le v < M} \mathrm{firstpos}(v,\ i)
$$

**为什么"切得越短越好"**：所有使段 MEX $= M$ 的右端点都能让当前元素取到 $M$，第一项无法再区分，比较就落到后续项上。取最短的 $j$ 后，剩余后缀 $a[j+1..n]$ 是任何更长切法所得后缀的**超集**（更长切法的剩余部分是它的后缀），所以后续每一步可取的 MEX 都不小于对方，最终 $b$ 在剩余部分逐位不劣、长度也不短。这也解释了为什么字典序定义里"前缀更短者更小"是安全的：多出来的项都不会比缺少时的对应项更小。

**算法流程**：

1. 预处理 `idx[v]`：数值 $v$ 出现的所有下标（天然递增）。
2. 从当前起点 $i$ 开始，令 $k = 0, 1, 2, \dots$ 依次在 `idx[k]` 上二分查找第一个 $\ge i$ 的位置：
    - 找到：用该位置更新段的右端点 `j = max(j, 位置)`，继续考察 $k+1$；
    - 找不到：说明 $k$ 在剩余后缀中缺席，于是 $M = k$，把 $k$ 追加到答案，本段结束。
3. 从 $j + 1$ 继续下一段，直到处理完整个数组。

因为 $0 \le a_i \le n$，MEX 不会超过 $n$，所以 $k$ 枚举到 $n$ 就足够。

### 复杂度

- 时间：$O(n \log n)$
- 空间：$O(n)$

每段内层循环执行 $M+1$ 次，而段内至少要装下 $0 \sim M-1$ 共 $M$ 个不同值，故 $M+1 \le$ 段长 $+1$；所有段长之和为 $n$，内层总迭代 $O(n)$ 次，每次 `lower_bound` 为 $O(\log n)$。

两处容易写错的地方：一是**右端点必须覆盖 $0 \sim M-1$ 的首次出现**，若只按上界随手切一段，段内可能缺某个值，MEX 就达不到 $M$，答案会偏小；二是代码用 `idx[A[i]]` 直接按值建桶，桶大小只有 $n+1$，若出现 $a_i > n$ 会越界（题目保证 $a_i \le n$，但调试时手造不合法的数据会触发段错误）。

## 样例

### Sample 1（官方样例，基本功能）

**输入：**

```
6
5
1 0 2 0 3
8
2 2 3 4 0 1 2 0
1
1
5
0 1 2 3 4
4
0 1 1 0
10
0 0 2 1 1 1 0 0 1 1
```

**输出：**

```
1
4
2
5 1
1
0
1
5
2
2 2
4
3 2 2 0
```

**说明：** 第 1 组的后缀 MEX 为 $4$，整段只能得到 $4$，故 $b = [4]$；第 5 组 $a = [0,1,1,0]$ 的第一段取 $[0,1]$ 得 MEX $2$，剩余 $[1,0]$ 再得 MEX $2$，故 $b = [2,2]$。

---

### Sample 2（坑点：段要切得最早，长度也参与字典序比较）

**输入：**

```
1
6
0 1 2 0 1 2
```

**输出：**

```
2
3 3
```

**说明：** 整段取完只能得到 $b = [3]$；而在第一次就切在位置 $3$（段 $[0,1,2]$，MEX $3$）后，剩余 $[0,1,2]$ 还能再得一个 $3$，得到 $[3,3]$。由于 $[3]$ 是 $[3,3]$ 的前缀，$[3,3]$ 更大——这正是"切得越早越好"的意义。

---

### Sample 3（边界：$n = 1$）

**输入：**

```
2
1
0
1
1
```

**输出：**

```
1
1
1
0
```

**说明：** 单元素数组只会产生一项。$[0]$ 这一段含 $0$，MEX 为 $1$；$[1]$ 的段内没有 $0$，MEX 为 $0$——MEX 是「缺失的最小非负整数」，只有含 $0$ 的段才可能取到 $1$ 以上。

---

### Sample 4（极端数据：所有元素相同，答案全为 $0$）

**输入：**

```
1
5
3 3 3 3 3
```

**输出：**

```
5
0 0 0 0 0
```

**说明：** $0$ 在整个数组中缺席，任何段的 MEX 都是 $0$；而"切得越早越好"使得每段只取一个元素，长度取到最大 $n$。
