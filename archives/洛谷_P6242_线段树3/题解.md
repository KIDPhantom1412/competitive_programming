- **来源**：洛谷 P6242

- **日期**：2026-08-16

## 一句话题目

维护序列 A 的区间加、区间对 v 取 min，并支持询问区间和、区间最大值，以及历史最大值数组 B（每次操作后 B = max(B, A)）的区间最大值。

## 一句话题解

吉司机线段树（Segment Tree Beats）：节点维护最大值/次大值/最大值个数，区间加拆成「最大值集合」与「非最大值集合」两个加法标记（mxda/da），chmin 只需减小最大值集合；再为两类标记各维护历史最大值（mxdb/db）回答历史最值。

## 题目描述

给出一个长度为 n 的数列 A，同时定义辅助数组 B，B 开始与 A 完全相同。进行 m 次操作，共五种：

- `1 l r k`：对 i ∈ [l, r]，A_i += k（k 可为负）
- `2 l r v`：对 i ∈ [l, r]，A_i = min(A_i, v)
- `3 l r`：求 Σ A_i
- `4 l r`：求 max A_i
- `5 l r`：求 max B_i

每次操作后更新 B_i = max(B_i, A_i)。

**数据范围**：1 ≤ n, m ≤ 5×10^5；-5×10^8 ≤ A_i, v ≤ 5×10^8；-2000 ≤ k ≤ 2000；1 ≤ l ≤ r ≤ n。

## 解法 1：Segment Tree Beats（吉司机线段树）

### 思路

**节点信息**：

- `sum`：区间和
- `mx1`：区间最大值；`mx2`：次大值（不存在为 -INF）；`cnt`：最大值个数
- `mxb`：区间历史最大值
- `mxda`/`da`：最大值集合 / 非最大值集合的加法标记（相对于自身集合的累积增量）
- `mxdb`/`db`：`mxda`/`da` 在标记生命周期内的历史最大值

**区间加 d**：全体元素加 d。`sum += d·len`，`mx1/mx2 += d`，`mxb = max(mxb, mx1)`；两个加法标记都累加：`mxda += d; da += d`，历史标记更新为新值的历史最大：`mxdb = max(mxdb, mxda); db = max(db, da)`（必须先累加再取 max）。

**区间 chmin(v)**：

1. `v >= mx1`：无影响，直接返回（剪枝）
2. 完全覆盖且 `v > mx2`：只有最大值集合受影响——`sum -= (mx1-v)·cnt`，`mxda -= (mx1-v)`，`mx1 = v`，直接打标记返回（mxb 不变：A 变小不影响历史最大）
3. 否则递归下钻，pull

**push**：

- 父节点的最大值标记只应下传给「子节点最大值元素 ⊆ 父节点最大值元素」的子节点。**关键坑点**：父节点被 chmin 后 `mx1[u]` 已降低，而子节点的 `mx1` 仍是旧值，直接比较 `mx1[child] == mx1[u]` 会错发标记。正确做法是拿子节点 `mx1` 与父节点剔除自身标记后的底层最大值比较：`mx1[child] == mx1[u] - mxda[u]`（子节点 mx1 已含自身标记，不能再减 `mxda[child]`）
- 命中则传 `(da, db, mxda, mxdb)`，否则子节点的最大值元素对父节点而言是非最大值，传 `(da, db, da, db)`
- 下传后必须清空父节点四枚标记

**pushTag 的标记合并**（子节点可能已有存量标记）：先算历史最大再累加：

```cpp
sum += mxda*cnt + da*(len-cnt);
mxb = max(mxb, mx1 + mxdb);          // 用旧 mx1
mx1 += mxda;
if (mx2 != -INF) mx2 += da;
db   = max(db,   da + db参数);   da   += da参数;   // 用旧 da/mxda
mxdb = max(mxdb, mxda + mxdb参数); mxda += mxda参数;
```

### 复杂度

- 时间：O((n + m) log n)（势能分析，chmin 均摊 O(log n)）
- 空间：O(n)（节点结构体 9 个字段，约 144 MB @ n = 5×10^5，512 MB 内存限制内）

见 `correct_code_01.cpp`。

### 坑点

1. **覆盖判断笔误**：`add` 中 `if (L >= l && R <= l)` 应为 `R <= r`。原写法仅在区间恰为单点 l 时命中，否则无限递归导致段错误（样例直接 RE）。
2. **push 未清空父节点标记**：下传后 `da/db/mxda/mxdb` 未清零，标记会被重复叠加。
3. **历史最大标记维护错误**：`db = max(db, d)` 应为 `db = max(db, da + d)`（在 da 累加后）；pushTag 中同理，且必须先取旧值（`max(旧db, 旧da + 父db)`）再累加。
4. **push 归属判断错误**：`mx1[child] == mx1[u]` 在父节点 chmin 后失效，最大值标记错发给非最大值子节点、真正最大值元素丢失标记。改用 `mx1[child] == mx1[u] - mxda[u]`（曾误写成再减 `mxda[child]`，被对拍反例抓出：子节点自带 chmin 标记时其 mx1 已含自身标记）。

## 样例

### Sample 1（基本功能）

**输入：**

```
5 6
1 2 3 4 5
3 2 5
1 1 3 3
4 2 4
2 3 4 1
5 1 5
3 1 4
```

**输出：**

```
14
6
6
11
```

**说明：** 官方样例，覆盖全部五种操作。

---

### Sample 2（坑点：chmin 后 push 归属判断）

**输入：**

```
5 3
-5 10 -3 -6 -3
2 2 2 7
2 1 3 4
4 2 4
```

**输出：**

```
4
```

**说明：** 先对 [2,2] chmin 到 7，再对 [1,3] chmin 到 4：第二次 chmin 在内部节点打标记，查询时 push 若用 `mx1[child] == mx1[u]` 判断会漏发标记，错误输出 7（A₂ 未被降到 4）。

---

### Sample 3（坑点：子节点自带 chmin 标记）

**输入：**

```
4 10
-7 2 5 -6
1 1 1 4
5 3 3
2 3 4 -5
1 3 3 -8
3 3 3
2 3 4 10
3 1 3
4 2 2
2 4 4 -8
5 3 3
```

**输出：**

```
5
-13
-14
2
5
```

**说明：** 对拍反例（seed=4）。节点 [3,4] chmin 后其子节点 [3,3] 仍持旧 mx1，若 push 判断再错误地减去子节点自身 mxda 同样会丢标记。
