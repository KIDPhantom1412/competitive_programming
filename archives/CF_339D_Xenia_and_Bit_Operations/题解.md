# CF_339D_Xenia_and_Bit_Operations

- **来源**：[Codeforces Round 197 (Div. 2) D - Xenia and Bit Operations](https://codeforces.com/problemset/problem/339/D)（rating 1700）
- **标签**：线段树、位运算、完全二叉树
- **日期**：2026-10-21

## 一句话题目

给定长度 $2^n$ 的序列，每轮把相邻两个元素合并（第 $1$ 轮按位或、第 $2$ 轮按位异或，之后交替），直到只剩一个数 $v$；有 $m$ 次单点修改，每次修改后输出当前的 $v$。

## 一句话题解

这一串合并正好是一棵完全二叉树，线段树每个节点记录「本层的运算是 OR 还是 XOR」，自底向上交替推出，单点修改后沿路径重算到根即可。

## 题目描述

Xenia 有一个长度 $2^n$ 的非负整数序列 $a_1, a_2, \ldots, a_{2^n}$。她按如下方式计算 $v$：

- 第 $1$ 次迭代：写出新序列 $a_1 \text{ or } a_2,\ a_3 \text{ or } a_4,\ \ldots,\ a_{2^n-1} \text{ or } a_{2^n}$，长度为 $2^{n-1}$；
- 第 $2$ 次迭代：对上一次得到的序列做**按位异或**的相邻合并，长度变为 $2^{n-2}$；
- 按位或、按位异或交替进行，直到序列只剩一个元素，该元素就是 $v$。

例如 $a = (1, 2, 3, 4)$：$(1, 2, 3, 4) \to (1 \text{ or } 2 = 3,\ 3 \text{ or } 3 = 3,\ 3 \text{ or } 4 = 7) \to (3 \text{ xor } 3 = 0,\ 3 \text{ xor } 7 = 4)$，所以 $v = 4$。

现在给出初始序列和 $m$ 次询问，每次询问是一对整数 $p, b$，表示令 $a_p = b$（**赋值，不是加法**），询问后要输出新序列对应的 $v$。

**输入格式**：第一行 $n, m$；第二行 $2^n$ 个整数 $a_1, \ldots, a_{2^n}$；接下来 $m$ 行每行 $p, b$。

**输出格式**：输出 $m$ 行，每行一个整数，表示该次询问后序列对应的 $v$。

**数据范围**：$1 \le n \le 17$，$1 \le m \le 10^5$，$0 \le a_i < 2^{30}$，$1 \le p \le 2^n$，$0 \le b < 2^{30}$。

## 解法 1：线段树维护每层运算类型

### 思路

**第一步：把合并过程看成树。**

把初始的 $2^n$ 个元素放成一棵完全二叉树的叶子，第 $1$ 轮合并就是把每对兄弟做 OR 得到父节点，第 $2$ 轮就是对上一层做 XOR 得到更上一层的父节点……一直到根为 $v$。所以整题就是：**叶子是 $a_i$，第 $k$ 层（从底层往上数，$k = 1$ 表示叶子上面那一层）做 OR 当 $k$ 为奇数、做 XOR 当 $k$ 为偶数，求根的值**，并支持叶子单点修改。

**第二步：节点记录什么。**

线段树的每个节点存两个信息：

- `v`：该子树合并出来的值；
- `isOr`：本节点是由左右儿子做 OR 还是做 XOR 合并而来。

叶子没有合并操作，`isOr` 随便取 `false`。由于运算严格逐层交替，父节点的类型必然是子节点类型的**取反**：

$$
\text{isOr}(\text{parent}) = \lnot \text{isOr}(\text{child})
$$

于是建树时自底向上用 `tr[u].isOr = !tr[lc].isOr` 推一遍，就不需要手算层数和奇偶。检查一下小数据：叶子 `false`，其父为 `true`（OR，对应第 $1$ 轮），根的类型自然等于「$n$ 为奇数就 OR，$n$ 为偶数就 XOR」，与实际过程一致。

**第三步：修改与查询。**

单点赋值的修改只影响从叶子到根的 $O(\log 2^n) = O(n)$ 个节点，递归回溯时 `pull` 重算即可；根节点的值就是答案，无需额外查询函数。

**小优化**：`isOr` 完全由深度决定，也可以把类型折进递归参数（`build(u, L, R, isOr)`），省掉一个字段；两种写法等价，下面代码用字段版，读起来更直观。

### 复杂度

- 时间：建树 $O(2^n)$，每次修改与输出 $O(n)$，总计 $O(2^n + mn)$
- 空间：$O(2^n)$

### 坑点

未记录（本次归档没有留下调试记录）。需要留意的地方：

- 运算类型只看**深度奇偶**，不要按「当前区间长度」判断，否则容易把根层的运算写反；
- 用「从儿子取反」的方式推类型，比手算 $n$ 的奇偶更不容易出错；
- 询问是**赋值** `a[p] = b`，不是累加，更新时直接覆盖叶子的值。

## 样例

### Sample 1（基本功能）

**输入：**

```
2 4
1 6 3 5
1 4
3 4
1 2
1 2
```

**输出：**

```
1
3
3
3
```

**说明：** $a = (4, 6, 3, 5) \to (4|6=6,\ 3|5=7) \to 6 \oplus 7 = 1$，后续询问同理。

---

### Sample 2（边界：$n = 1$）

**输入：**

```
1 3
5 3
1 7
2 0
2 5
```

**输出：**

```
7
7
7
```

**说明：** $n = 1$ 时只有一轮 OR，答案是 $a_1 \text{ or } a_2$；注意最后一次修改后 $a = (7, 5)$，仍得 $7$。

---

### Sample 3（坑点：OR 与 XOR 的交替顺序）

**输入：**

```
2 1
1 2 3 4
1 1
```

**输出：**

```
4
```

**说明：** 题面例子原样验证。先 OR 得到 $(3, 3, 7)$，再 XOR 得到 $(0, 4)$，最后 OR 得到 $4$；若把两种运算的顺序弄反（先 XOR 再 OR），会得到 $(1 \oplus 2 = 3,\ 3 \oplus 4 = 7) \to 3 \text{ or } 7 = 7$，与正确答案不同，适合用来检验层类型是否写对。
