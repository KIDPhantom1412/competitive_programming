# HDU 5306 Gorgeous Sequence

- **来源**：HDU 5306
- **标签**：线段树、Segment Tree Beats、区间最值、区间求和、区间 chmin
- **日期**：2026-08-14

## 一句话题目

维护一个序列，支持区间 `chmin`、区间最大值查询、区间和查询。

## 一句话题解

使用 Segment Tree Beats 维护每个区间的最大值、次大值、最大值出现次数以及区间和，从而将区间 `chmin` 做到均摊 `O(log n)`。

## 题目描述

给定一个长度为 `n` 的序列 `a`，需要执行 `m` 次操作，操作共有三种：

- `0 x y t`：对于所有 `x ≤ i ≤ y`，令 `a_i = min(a_i, t)`。
- `1 x y`：输出 `max{a_i | x ≤ i ≤ y}`。
- `2 x y`：输出 `sum{a_i | x ≤ i ≤ y}`。

### 输入格式

第一行一个整数 `T`，表示测试组数。

每组数据第一行两个整数 `n, m`。

第二行 `n` 个整数 `a_1, ..., a_n`。

接下来 `m` 行，每行一个操作。

### 输出格式

对于每个类型为 `1` 或 `2` 的操作，输出一行答案。

### 数据范围

- `T = 100`
- `Σn ≤ 10^6`, `Σm ≤ 10^6`
- `0 ≤ a_i, t < 2^31`

## 解法 1：Segment Tree Beats

### 思路

区间 `chmin` 若用普通线段树暴力修改会退化到 `O(n)`。Segment Tree Beats 的核心思想是：

每个节点维护：

- `mx1`：区间最大值。
- `mx2`：区间次大值（严格小于 `mx1`）。
- `cnt`：`mx1` 出现的次数。
- `sum`：区间和。

对于一次区间 `chmin(x)`：

1. 若 `x >= mx1`，无需修改。
2. 若 `mx2 < x < mx1`，则只需要把最大值 `mx1` 降到 `x`，区间和减少 `(mx1 - x) * cnt`。
3. 否则需要继续下传到子节点。

通过均摊分析，每个元素被修改的次数有限，因此总复杂度为均摊 `O((n + m) log n)`。

### 复杂度

- 时间：均摊 `O((n + m) log n)` 每组数据
- 空间：`O(n)`

### 坑点

调试过程中遇到的主要错误及修复：

1. **`pull` 最大值合并错误**：原代码写成 `tr[u].mx1 = max(tr[lc].mx1, tr[rc].mx2)`，误把右子节点的次大值当作最大值，导致最大值错误。应正确比较两个子节点的 `mx1`。
2. **最大值相等时未合并 `mx2` 与 `cnt`**：当左右子节点 `mx1` 相等时，需要合并出现次数，并把 `mx2` 更新为左右子节点 `mx2` 的较大者。
3. **`push` 为空**：原代码没有下传 `chmin` 标记，导致子节点仍保存旧的最大值。修复后，父节点的 `mx1` 会正确下传给子节点（仅当子节点 `mx1` 更大时才需要更新）。
4. **查询未 `push`**：原 `queryMax` 与 `querySum` 没有下传标记，访问到的子节点可能是旧值。修复后在进入子节点前调用 `push`。
5. **数据类型溢出**：原代码用 `int` 存 `sum` 与节点值，但区间和与 `(mx1 - a) * cnt` 都可能超过 `int` 范围，需改用 `long long`。
6. **`update` 中 `L == R` 的特殊处理冗余且容易出错**：统一交由 `pull` / `push` 处理即可。
