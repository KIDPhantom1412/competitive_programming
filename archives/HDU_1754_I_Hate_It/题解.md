## 一句话题目

维护 N 个学生的成绩，支持两种操作：询问 ID 在 [A, B] 内的最高成绩；把 ID 为 A 的学生成绩更改为 B。

## 一句话题解

用「区间最大值型树状数组」：`tr[i]` 维护 `(i - lowbit(i), i]` 的最大值，单点更新沿祖先链 `i += lowbit(i)` 分升值/降值两种情况维护，区间查询从右往左整块跳过，每次操作 O(log² n)。

## 题目描述

很多学校流行一种比较的习惯。老师们很喜欢询问，从某某到某某当中，分数最高的是多少。这让很多学生很反感。现在需要写一个程序模拟老师的询问，老师有时候也需要更新某位学生的成绩。

**输入**：本题目包含多组测试，请处理到文件结束。

- 每组测试第一行有两个正整数 N 和 M（0 < N ≤ 200000，0 < M < 5000），分别代表学生的数目和操作的数目。学生 ID 从 1 编到 N。
- 第二行包含 N 个整数，第 i 个数代表 ID 为 i 的学生的初始成绩。
- 接下来 M 行，每行一个字符 C（只取 'Q' 或 'U'）和两个正整数 A、B：
  - `Q A B`：询问 ID 从 A 到 B（包括 A、B）的学生中成绩最高是多少（保证 A ≤ B）。
  - `U A B`：把 ID 为 A 的学生的成绩更改为 B。

**输出**：对于每一次询问操作，在一行里输出最高成绩。

**提示**：Huge input, the C function scanf() will work better than cin（用 cin 需关同步流）。

## 解法 1：树状数组（区间最大值型 BIT）

### 思路

常规 BIT 维护的是前缀和，靠「减法」做区间查询；但 **max 没有逆运算**，不能把 `query(l, r)` 拆成 `前缀max(r) - 前缀max(l-1)`。因此 max 型 BIT 需要专门设计 update 和 query：

**`update(x, v)` —— 单点更新**

- `tr[i]` 管辖区间 `(i - lowbit(i), i]`。修改 `A[x]` 会影响所有覆盖 x 的 BIT 节点，即从 x 出发沿 `i += lowbit(i)` 的祖先链，共 O(log n) 个节点。
- 关键观察：先比较新值 v 和**旧值** `A[x]`（不是 `tr[x]`）：
  - **升值（v ≥ 旧 A[x]）**：区间最大值要么不变、要么变成 v，直接 `tr[i] = max(tr[i], v)`，每个节点 O(1)。
  - **降值（v < 旧 A[x]）**：被改的位置 x 可能正是原来的最大值来源，光取 max 无法「删掉」旧值，必须**重算整个管辖区间**。`tr[i]` 的区间 `(i - lowbit(i), i]` 可以按二进制分裂为 `A[i]` 加上 `tr[i-1], tr[i-2], tr[i-4], ...`（即 `tr[i-j]`，`j` 取遍小于 `lowbit(i)` 的 2 的幂），共 O(log n) 个候选，取 max 即可。
- 总复杂度：升值 O(log n)，降值 O(log² n)。注意必须先把 `up` 判断出来**再**写 `A[x] = v`，且判断对象是 `A[x]` 而不是 `tr[x]`。

**`query(l, r)` —— 区间最大值查询**

- max 不可逆，无法像求和 BIT 那样从两端下跳，只能**从右端点 r 往左扫**。
- 设当前右端点为 i（不变式：`res` 已保存 `(i, r]` 的最大值）：
  - 若 `tr[i]` 管辖的整块 `[i - lowbit(i) + 1, i]` 完全落在 `[l, r]` 内，直接 `res = max(res, tr[i])`，然后把 i 跳到块左端点再 -1，**整块跳过**；
  - 否则（块左端越出 l），只能逐点取 `A[i]`，i 左移一格。
- 每一轮至少消耗一个位置，而连续两次取单点的情形最多出现 O(log n) 次（因为单个点消耗完后，下一次的 `lowbit(i)` 会变大），故总复杂度 O(log n)。

由于 M < 5000、N ≤ 2×10⁵，这个 `O((N + M) log² N)` 的做法绰绰有余；本题同样是「单点修改 + 区间 max」的**线段树**模板题，两种写法都可以通过。

### 复杂度

- 时间：建树 O(N log N)，每次操作 O(log² N)（升值更新与查询为 O(log N)）
- 空间：O(N)

### 坑点

- **`update` 中必须用旧值 `A[x]` 判断升降值**：第一版误写成 `bool up = v >= tr[x]`。`tr[x]` 是 `(x - lowbit(x), x]` 的区间最大值而非 x 本身的值，当区间内其它位置比 x 大时，会把「降值」误判为「升值」，跳过重算分支，导致降值后 `tr` 仍残留旧最大值、查询结果偏大。修复：`v >= A[x]`，且判断要在 `A[x] = v` 赋值之前。
- **多组数据必须重置 `tr`**：`while (cin >> n >> m)` 处理到文件结束，每组数据开头 `fill(tr + 1, tr + 1 + n, 0)`，否则上一组的值会污染（本题成绩为正整数，置 0 即可）。
- **`query` 中整块跳过的写法**：`i = j` 后靠循环自带的 `i--` 落到 `j - 1`，若手写 `i = j - 1` 会跳错。
- **大数据输入**：原题 hint 提示 scanf 优于 cin；用 cin 时需 `ios::sync_with_stdio(false); cin.tie(nullptr);`。

## 样例

### Sample 1（基本功能）

**输入：**
```
5 6
1 2 3 4 5
Q 1 5
U 3 6
Q 3 4
Q 4 5
U 2 9
Q 1 5
```

**输出：**
```
5
6
5
9
```

**说明：** 原题样例。依次覆盖：全区间查询、升值更新后查询（max 变大）、不包含更新位置的查询（max 不变）、再次升值后全区间查询。

---

### Sample 2（坑点：降值更新）

**输入：**
```
3 4
1 9 3
Q 1 3
U 2 1
Q 1 3
```

**输出：**
```
9
3
```

**说明：** 把区间最大值所在位置改小后，`tr` 必须重算才能得出新的最大值 3；第一版 `v >= tr[x]` 的误判会使第二次查询仍输出 9，正是该 bug 的暴露用例。
