# OpenJ_Bailian_1144_Network

- **来源**：OpenJ_Bailian 1144（UVA 315 Network，Central Europe 1996）
- **标签**：图论、Tarjan、割点、输入解析
- **日期**：2026-11-18

## 一句话题目

给定一个无向网络，求它的**割点**（去掉该点后会使网络不再连通的点，即“关键地点”）的数量，多组数据。

## 一句话题解

一遍 Tarjan DFS 求出 `dfn` 与 `low`：若树边儿子 $v$ 满足 `low[v] >= dfn[u]`，则 $u$ 是割点；根节点需要至少两个儿子才是割点。

## 题目描述

电话线路公司（TLC）正在建设新的电话电缆网络，连接若干个地点，编号 $1$ 到 $N$。线路都是双向的，每条线路恰好连接两个地点，每个地点都设有一部电话交换机。从任意地点出发都可以通过线路到达其他所有地点（不一定直达，可经过若干交换机）。

偶尔某个地点会发生供电故障，导致该处的交换机停止工作。TLC 的工作人员发现，这种故障除了会让故障地点本身无法到达外，还可能导致其他一些地点之间无法互通。这种情况发生时，称该故障地点为“关键地点”。求所有关键地点的数量。

- **输入**：文件由若干数据块组成，每个数据块描述一个网络。
  - 每个数据块的第一行是地点数量 $N$。
  - 接下来的**至多 $N$ 行**，每行先给出一个地点编号，随后列出若干个与该地点有直接线路连接的地点编号，即该行给出以这个地点为一个端点的所有边；这至多 $N$ 行会完整描述整个网络（**每条边至少出现在其中一行里**，因此同一条边可能在两个端点的行里各出现一次）。
  - 每行中所有数字以一个空格分隔。每个数据块以单独一行 `0` 结束。
  - 最后一个数据块只有一行，即 $N = 0$。
- **输出**：对除最后一个数据块之外的每个数据块输出一行，包含关键地点的数量。
- **数据范围**：$N < 100$；时间限制 1000 ms，内存限制 65536 KB。
- **提示**：需要判断一行在哪里结束，每行末尾不会多出额外的空格。

## 解法 1：Tarjan 求割点

### 思路

对图做一遍 DFS，记录访问时间戳 $dfn_u$ 和 $low_u$：

$$
low_u = \min\big(\{dfn_u\} \cup \{dfn_w \mid w \text{ 是 } u \text{ 子树中某点的后向边终点}\} \cup \{low_v \mid v \text{ 是 } u \text{ 的儿子}\}\big)
$$

即 `low[u]` 表示 $u$ 及其子树内的点，不经过 $u$ 的父亲就能回到的**最早**的访问时间。

对 $u$ 的每个树边儿子 $v$（`dfn[v] == 0`，并且遍历时跳过父节点 `fa`）：

1. 递归进入 $v$，回溯后做 `low[u] = min(low[u], low[v])`；
2. 若 `u != root` 且 `low[v] >= dfn[u]`，说明 $v$ 的子树无法绕过 $u$ 回到 $u$ 的祖先，删掉 $u$ 后 $v$ 的子树就与祖先部分断开，$u$ 是割点。

对于非树边（后向边，`dfn[v] != 0` 且 `dfn[v] < dfn[u]`），用祖先的时间戳更新 `low[u] = min(low[u], dfn[v])`。

根节点 `root` 没有祖先可回退，割点条件改为“子树个数 `cnt >= 2`”。

由于题目不保证图连通，需要对每个未访问点各起一次 DFS，并在每次 DFS 前把 `root` 设为该起点。

### 复杂度

- 时间：每组 $O(N + M)$，其中 $M$ 为边数（输入中每条边可能写两次，仍是常数倍）。
- 空间：$O(N + M)$。

### 坑点

1. **割点判据写成了 `low[v] >= low[u]`（正确为 `low[v] >= dfn[u]`）**。
   回溯时刚执行过 `low[u] = min(low[u], low[v])`，此时必然有 `low[u] <= low[v]`，条件**恒为真**，于是所有“有树边儿子的非根点”都被记成割点，答案系统性偏大。

2. **割点判定放在了树边分支之外**。
   只有在 `dfn[v] == 0` 时才可以把 `v` 当作 `u` 的儿子做 `low[v] >= dfn[u]` 判定。若把判定提到 `if/else-if` 之后，当 `v` 是**已访问的后代**时也会执行该判定（本题目输入允许同一条边在两个端点的行中各写一次，从而产生这种情形），`low[v]` 已计算完毕，可能满足 `low[v] >= dfn[u]`，把本不是割点的 $u$ 误判为割点。

3. **两个 bug 叠加时样例仍然会过**。
   题目两个样例一个是以 $5$ 为中心的星形图、一个是 $1-2-3$ 与 $2-5$ 的组合图，错误答案恰好与正确答案相同，因此样例通过**不能**作为正确性判据，需要自己构造重复边、树形、链形数据验证。

4. **`std::reduce` 需要 C++17**。
   老评测机（C++11 及更早）会编译失败，应改用 `std::accumulate`（`<numeric>` 中，语义等价），取初值 `0` 累加计数数组。

5. **`N` 与逐行读入混用**。
   用 `cin >> n` 读入 $N$ 后会残留一个换行，随后的 `getline` 会先读到空行。代码中用“空行则 `continue`”处理，但若某行末尾有多余空格或 `\r`，`line` 就不再为空，需要额外小心。

## 样例

### Sample 1（基本功能，题目原样例）

**输入：**
```
5
5 1 2 3 4
0
6
2 1 3
5 4 6 2
0
0
```

**输出：**
```
1
2
```

**说明：** 第 1 组是以 $5$ 为中心的星形图，只有 $5$ 是割点；第 2 组为 $1-2-3$ 与 $2-5-4,5-6$，割点是 $2$ 和 $5$。

---

### Sample 2（坑点：同一条边在两个端点的行中重复出现）

**输入：**
```
5
1 5 3 2
2 1 4 5
3 1
4 2 5
5 2 1 4
0
```

**输出：**
```
1
```

**说明：** 边集为 $1-5,1-3,1-2,2-4,2-5,4-5$（每行都从该点视角重复列了一遍邻点），唯一割点是 $1$。若把割点判定放在树边分支之外，$5$ 会被误判，输出 $2$；若同时把判据写成 `low[v] >= low[u]`，输出 $4$。

---

### Sample 3（边界：只有一个地点）

**输入：**
```
1
0
0
```

**输出：**
```
0
```

**说明：** $N = 1$ 且没有任何线路，不存在关键地点。

---

### Sample 4（边界：两个地点一条线路）

**输入：**
```
2
1 2
0
0
```

**输出：**
```
0
```

**说明：** 去掉任意一个点，剩下的点只剩它自己，“连通块个数”没有增加，因此两点都不是割点。

---

### Sample 5（极端数据：链，考察根节点特判）

**输入：**
```
4
1 2
2 3
3 4
0
0
```

**输出：**
```
2
```

**说明：** 链 $1-2-3-4$ 中 $2,3$ 是割点；根 $1$ 只有一个儿子，按 `cnt >= 2` 的条件正确地没有被计入。
