# CF2259E Treasure Map Destruction (Constructive Version)

- **来源**：Codeforces 2259E（Codeforces Round 1119 Div. 3）
- **标签**：构造、差分、贪心
- **日期**：2026-09-13

## 一句话题目

给定一个被 $-1$ 部分破坏的数组 $b$（$b[i]$ 表示从岛 $i$ 到最近宝藏的距离），构造任意一个非空宝藏岛集，使得所有已知位的距离恰好等于 $b[i]$，无解输出 `-1`。

## 一句话题解

对每个已知的 $b[i] > 0$，用差分把开区间 $(i-b[i], i+b[i])$（即距离严格小于 $b[i]$ 的位置）标成禁放区，再检查每个已知 $i$ 的 $i-b[i]$、$i+b[i]$ 中至少有一个可放；禁放区取补集就是答案。$b[i] = 0$ 的禁放区间为空但强制 $i$ 放宝，落在禁放区即为无解。

## 题目描述

有 $n$ 座岛排成一行，Bessie 在若干座岛上埋了宝藏（至少一座）。对每座岛 $i$，定义 $a[i]$ 为从 $i$ 出发、每次只能走到相邻岛、到达任一有宝藏的岛所需经过的最少岛数，即 $a[i] = \min\{ |i - j| : j \text{ 上埋有宝藏} \}$。

现在部分 $a[i]$ 被破坏成了 $-1$，给出破坏后的数组 $b$。请输出任意一个可能的宝藏分布（长度为 $n$ 的 $01$ 串，第 $i$ 位为 $1$ 表示 $i$ 上埋宝），若不存在则输出 `-1`。答案必须包含至少一个宝藏。

**输入格式**：第一行 `t`；每组第一行 `n`，第二行 $n$ 个整数 $b$。

**数据范围**：$1 \le t \le 10^4$，$1 \le n \le 2 \times 10^5$，$\sum n \le 2 \times 10^5$，$-1 \le b[i] \le n-1$。

**记号约定**：题面把输入数组记作 $b$，代码里它被读入 $1$-based 的数组 `B`，即 `B[i]` 就是 $b[i]$；`diff`、`st` 是为实现引入的辅助数组，其中 `st[i]` 表示 $i$ 是否落在禁放区。下文正文论述统一用题面的 $b$，`B`、`diff`、`st` 只出现在代码片段或对代码的说明里。

## 解法 1：差分标记禁放区 + 取补集构造

### 思路

$a[i] = b[i]$ 这一条约束可以拆成两部分：

1. **不能更近**：所有满足 $|i - v| < b[i]$ 的位置 $v$ 都不能有宝藏。当 $b[i] > 0$ 时这就是开区间 $(i - b[i], i + b[i])$，即整数区间 $[i - b[i] + 1, i + b[i] - 1]$；用差分数组区间加 $1$ 标记，前缀和大于 $0$ 的位置记为禁放区（实现中记在 `st[v]`）。
2. **不能更远**：$i - b[i]$、$i + b[i]$ 中至少有一个在范围内且可放宝藏，否则最近宝藏距离会大于 $b[i]$，无解。

$b[i] = 0$ 时：$i$ 本身必须是宝藏（距离 $0$），但它的禁放区间是空的，**不应往差分里写任何东西**。因为 $i$ 不在自己的禁放区间内，只要别的约束没有禁放 $i$，取补集时它自然就是宝藏；若被别的约束禁放，则第 $2$ 条的检查恰好退化成「检查 $i$ 是否被禁放」（实现中的 `st[i]`），会正确报无解。

构造方式取「所有非禁放位置」这一最大集合：任何合法解的宝藏集合都必须是禁放区的子集（禁止项是强制的），而多放宝藏不会破坏「不能更近」（禁放区已挡住），反而更容易满足「恰好距离 $b[i]$ 处有宝藏」；未被约束的位置 $a$ 值任意，故不做限制。于是该集合合法时即为答案，且必非空（若全为禁放区，则第 $2$ 条检查对任一已知 $i$ 都会失败）。

### 复杂度

- 时间：$O(n)$ 每组，总体 $O(\sum n)$
- 空间：$O(n)$

### 坑点

$b[i] = 0$ 的差分处理。最初的写法把判断条件写成 `B[i] >= 0`，让 $b[i] = 0$ 也进入了差分循环（下面引用原始代码，其中 `B[i]` 即 $b[i]$）：

```cpp
if (B[i] >= 0) {
    diff[std::max(1, i - B[i] + 1)]++;
    diff[std::min(n + 1, i + B[i])]--;
}
```

$b[i] = 0$ 时这组差分（`diff[i + 1]++` 与 `diff[i]--`）本意是「空区间」，但前缀和上等价于在位置 $i$ 处产生 $-1$，也就是主动把 $i$ 从禁放区里抹掉。后果：

- 漏判冲突：$b[i] = 0$ 要求 $i$ 放宝，而 $i$ 又被别的约束禁放（存在 $|i - j| < b[j]$）时应无解，代码却给出一个看似合法的解；
- 更隐蔽的是这个 $-1$ 会抵消别的约束在 $i$ 处留下的 $+1$，让本该禁放的位置变得可放。

修复方式：把判断条件由 `B[i] >= 0` 改成 `B[i] > 0`，即只在 $b[i] > 0$ 时才标记禁放区，跳过 $b[i] = 0$（其禁放区间本就为空）。

### Sample 2（坑点：b[i] = 0 与禁放区冲突）

**输入：**

```
1
3
-1 0 2
```

**输出：**

```
-1
```

**说明：** $b[2] = 0$ 要求 $2$ 号岛放宝，但 $b[3] = 2$ 要求 $3$ 号岛距离 $1$ 以内（即 $2$ 号岛）没有宝藏，矛盾故无解。最初的错误代码会输出 `110`，此时 $a[3] = 1 \ne 2$。

### Sample 3（边界：n = 1 与全 -1）

**输入：**

```
2
1
0
2
-1 -1
```

**输出：**

```

```

**说明：** 单岛时只能埋宝；全部元素被破坏时任意非空集合都合法，取全集即可。
